# 鼠标输入：第 3 步实机验收

2026-10-21，本机 Windows / Wallpaper Engine 2.8.42。输入服务沿用提交 `676f36b`，本步骤不修改生产接口。

## 重现

先配置本机 `we.config.json` 的引擎路径、CEF 调试端口，并构建原生捕获 helper。运行时须有正常交互用户会话，约一分钟保持系统鼠标不动；脚本只读光标位置，不阻止用户输入。

```powershell
npm.cmd test
node scripts/verify-mouse.mjs
node scripts/verify-scene.mjs
```

最新报告为 `.we-mcp/mouse-verification/report.json`，每次运行另存到其 `runs/<uuid>/report.json`，包括 MCP 调用、截图路径、瞳孔测量、光标坐标、清理错误及未验收内容。源样例为 `test/fixtures/mouse-eyes`，通过只读 root 导入受管工程，不增加公开模板枚举。

## 通过的范围

- 17 次有效鼠标移动，49 张截图（34 张 CEF、15 张原生窗口）。页面记录真实浏览器鼠标事件的坐标、无按键状态与事件计数，输入坐标误差允许 1 CSS 像素。
- 960×540 下覆盖中心、四方向、四角、不同半径及回到中心；640×480 下顺序验证中心、左侧和右下角。两种尺寸的 Web 预览是先后运行的。
- 独立 PNG 像素测量得到双眼瞳孔质心、包围盒与虹膜面积，验证方向、位移和椭圆限幅。960×540 下单侧水平位移约 92 像素，垂直约 52 像素；比较容差 2 像素，限幅容差 5%。
- 固定椭圆遮罩外没有超过阈值的像素变化（遮罩边界容差 2 像素、RGB 通道差阈值 8）。瞳孔包围盒变化不超过 2 像素；边缘虹膜允许按设计被遮罩裁切，保留面积在中心的 45%～105% 内。回到中心后的完整 CEF 像素与初始中心相同，无残影。
- 原生窗口中心及边缘两帧的瞳孔位移与 CEF 结果相符，允许 3 物理像素误差；不是仅依赖页面自报的位移。
- 并行打开的静止 Scene 对照，在 12 个输入测试点后中央画面区域均未变化。比较排除原生窗口标题栏和边框，不把装饰变化当作壁纸变化。静止对照没有鼠标响应，不能证明其完全未收到事件，因此不替代双 Web 的事件隔离验收。
- 每次有效调用前后，`GetPhysicalCursorPos` 读取的光标位置一致。首次有位置变化的运行被判为失败，用户确认保持鼠标不动后重跑通过。这里是前后采样，不是连续轨迹监测。[微软 API](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getphysicalcursorpos)
- 把自有测试页面导航至 `about:blank` 后，输入请求被拒绝；关闭预览后的旧 previewId 也被拒绝。测试专用 CDP 导航未暴露为通用 MCP 工具。
- 测试窗口关闭、工作区锁释放、活动预览登记为空；正常退出无清理错误。

PNG 解码器从原有 Scene 验收脚本提取到 `scripts/png.mjs`，只处理有界、非交错的 8-bit RGB/RGBA 引擎截图。Scene 编辑/回滚/重载实机闭环重新通过；不引入图像库。

## 已发现但未解决：两个 Web 同时运行

第一次尝试同时打开 960×540、640×480 两个 Web 样例：第一个返回 page-ready；第二个窗口存在，但没有匹配其工程副本的 CEF 页面，鼠标请求返回 `CEF_TARGET_UNAVAILABLE`，该尝试失败。

独立最小复现观察到：第二个渲染进程带同一个 9223 调试参数启动；9223 的监听属于第一个渲染进程。目标列表新增若干由 IPC/启动参数形似转换而来的 HTTP 页面，而不是第二个 `file:` 工程页；等待后仍然如此。本机记录位于忽略目录 `.we-mcp/mouse-dual-probe/7bf4be71-3e77-4615-84dc-b385ce8020c0/report.json`。

这提示引擎多实例、CEF 配置目录或启动参数转发存在交互问题，但根因尚未证实，不能据此断言仅是端口冲突。开发者社区也记录过调试系统改动与部分系统故障；该讨论不证明本机故障的具体原因。[Wallpaper Engine 开发者回复](https://steamcommunity.com/app/431960/discussions/2/569289747256649392/)

因此，最终脚本显式记录 Web-to-Web 并发隔离未覆盖，以静止原生 Scene 作对照，并顺序测试两种 Web 尺寸。这只证明已列出的能力；不将替代对照表述为两个 Web 同时运行通过。本步骤未改引擎配置、端口发现架构或输入实现，未加入系统光标回退。后续应单独定位此限制。

## 仍未验收

这是可测量的几何双眼样例，没有人物原画、平滑跟随、眨眼或眼睑形变。通过像素检查不代表任意人物眼睛都自然，也不代表通用视觉质量判定成立。原生 Scene 鼠标输入、两个 Web 并发、真实硬件鼠标等价性、缩放/混合 DPI、多屏、4K/HDR 和长时间压力场景仍未验收。
